# 미션 가챠

미션을 완료하면 점수가 쌓이고, 점수가 기준치에 도달하면 뽑기권이 생겨 가챠를 뽑을 수 있는 웹앱입니다.
팀(6) → 구역(팀당 5) → 구역원(구역당 약 10명) 구조를 그대로 반영했습니다.

## 실행 방법

```bash
npm install
npm run seed   # 데모 데이터 생성 (6팀 x 5구역 x 10명, 미션 12개, 가챠 아이템 9종)
npm run dev    # http://localhost:3000
```

## 로그인

- 이름 검색 + PIN 번호로 로그인합니다 (이메일/비밀번호 회원가입 없음).
- 데모 구역원 PIN: `1234`
- 관리자(전체관리자) PIN: `0000`

## 구조

- **구역원**: `/dashboard`에서 난이도별(쉬움/보통/어려움) 미션 체크, `/gacha`에서 뽑기.
  체크는 승인 절차 없이 바로 반영됩니다 (카톡방에서 서로 확인하는 용도이므로 단순화).
- **관리자**: `/admin` 전체 현황(팀별 점수·완료율 차트, 팀→구역→구역원 드릴다운),
  `/admin/org` 조직 관리(팀/구역/구역원 추가·수정·삭제, PIN 재설정),
  `/admin/missions` 미션 관리, `/admin/gacha` 가챠 아이템 및 뽑기권 전환 기준 관리.

## 뽑기권 산정 방식

미션마다 난이도별 점수(쉬움 10 / 보통 20 / 어려움 30, 자유 조정 가능)가 있고,
`/admin/gacha`의 "뽑기권 전환 기준" 점수(기본 100점)를 모으면 뽑기권 1장이 생깁니다.
개수 기준(10개=1장)을 원하면 모든 미션 점수를 동일하게 두면 동일하게 동작합니다.

## 실제 명단 반영

지금은 데모용 무작위 인원 데이터가 들어있습니다. 실제 팀/구역/구역원 명단이 준비되면
`/admin/org`에서 하나씩 추가하거나, `prisma/seed.ts`를 실제 명단 기반으로 바꿔서
`npm run seed`로 다시 채울 수 있습니다.

## 배포 시 참고

- 현재 DB는 SQLite 로컬 파일(`prisma/dev.db`)입니다. 실제 서비스로 배포할 때는
  `prisma/schema.prisma`의 `datasource`를 Postgres 등으로 바꾸고 마이그레이션하세요.
- `src/lib/auth.ts`의 세션 서명 비밀키는 개발용 하드코딩 값입니다. 배포 전 환경변수 기반 비밀키로 교체하세요.
